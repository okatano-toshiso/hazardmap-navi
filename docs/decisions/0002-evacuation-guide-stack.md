## Context
- 2026-11-24、ユーザーがテーマを変更した: ハザードマップと避難場所を取得し、現在位置から避難場所・避難経路・連絡先を即座に示すアプリ。
  対象地域は大阪市此花区（万博会場の夢洲を含む）。AI には「最短ルートやハザードなど、今やるべきことをレクチャーさせ、レスキューの知識を持たせる」。
- 課題原文は「オープンデータや AI」。参考例に国土地理院・OpenStreetMap が挙がっている。
- 2026-11-24 に一次データを直接取得して確認した事実:
  - 指定緊急避難場所: 地理院タイル `https://cyberjapandata.gsi.go.jp/xyz/skhb0N/{z}/{x}/{y}.geojson`（N=1..8 は災害種別）。
    属性は `name`・`address`・`remarks`・`disaster1..8`（1=洪水, 2=崖崩れ等, 3=高潮, 4=地震, 5=津波, 6=大規模な火事, 7=内水氾濫, 8=火山）。電話番号はない。
    此花区の件数は 洪水80・地震60・津波81・**高潮0**（z10/897/406）。利用規約は PDL1.0（出典と加工の明記が必要）。
  - 浸水想定: ハザードマップポータル `https://disaportaldata.gsi.go.jp/raster/{layer}/{z}/{x}/{y}.png`（z2〜17、PDL1.0、アプリでの利用可）。
    画素色が凡例 `shinsui_legend3.png` の色と一致し、浸水深の区分を決定的に読める。
    例: 西九条付近 津波0.5〜1m・高潮3〜5m・洪水0.5〜3m、島屋付近 高潮5〜10m。
  - 此花区ハザードマップは「住宅地はほぼ全て浸水」「3階以上なら自宅で避難」と案内している。必ず避難所へ向かわせる案内は誤りになりうる。

## Decision
- **決定的な部分（命に関わるため AI に任せない）**
  - 現在地（ブラウザの位置情報、または地図クリック）の浸水深を、3種のハザードタイルの画素色から凡例で判定する。
  - 選んだ災害種別に対応する指定緊急避難場所だけを候補にし、徒歩経路で近い順に3件を出す。対応する場所がデータにない場合は「ない」と表示する。
  - 徒歩経路: OpenStreetMap の歩行者ネットワークを事前に取得してグラフにし、最短経路で計算する。
    取得と前処理は OSMnx（MIT、内部で NetworkX を使用）で行う開発時スクリプトに閉じる。
    実行時は保存済みグラフに対する自作の Dijkstra で計算し、地理系の重い依存を持たない。
  - 連絡先: 119・110・災害用伝言ダイヤル171・此花区役所など、出典を確認した固定リスト。
- **AI の役割**: 決定的に計算した事実（浸水深・避難先・距離・経路）と、公式資料から選んだ根拠の抜粋だけを渡し、
  「今やるべきこと」を短く説明させる（RAG）。再学習（ファインチューニング）はしない。
  経路や避難先を AI に作らせず、出力に事実にない場所・数値がないかを検査し、評価ケースで確かめる。
  呼び出しは、事前の写真比較の試作で検証した Claude Code CLI 経路（静的 API キーなし）を再利用し、ツールは与えない。
- **地図表示**: Leaflet（BSD-2-Clause、ローカルに同梱）＋地理院タイル（淡色地図）＋浸水想定タイルの重ね表示。
- Web: Flask + Jinja（ユーザー指定）。127.0.0.1 のみで待ち受け。

## Alternatives
- 経路を外部の経路 API（OSRM 公開サーバー等）に任せる: 利用ポリシーと可用性に依存し、オフラインで再現できないため不採用。
- AI に避難先や経路を決めさせる: 検証できず、誤りが命に関わるため不採用。
- ファインチューニングで防災知識を学ばせる: 1日で用意できず、出典を示せず、資料更新に追従できないため不採用。RAG で代替する。
- 全国対応: データ量と時間から不採用。此花区に限定する。

## Consequences
- データは随時更新されるため、取得日を画面と台帳に記録し、「最新の情報は大阪市・此花区で確認すること」を明示する。
- OSM 由来の経路には ODbL の出典表示（© OpenStreetMap contributors）が必要。
- 浸水深は想定であり、実際の災害時の状況とは異なりうることを画面で伝える。
- 戻し方: 新しいパッケージと data を削除すれば、ハーネスと企画文書だけの状態に戻る。
