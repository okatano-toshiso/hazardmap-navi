# 0003: EDEN SYSTEM（補足の試作）の構成

## Status
Accepted（2026-11-25、ユーザーが作成を指示）。メインの提出物はハザードマップナビ（ADR 0002）で、本試作は補足。

## Context
- 仕様は [eden-system-spec.md](../product/eden-system-spec.md)。場所（緯度経度）と、写真から AI が認識した建物・看板・モノにコメントを残す。
- ユーザー決定: パブリック／プライベート（友達のみ）、その場所にいるときだけ書ける、カメラ越し＋地図、広告は試作に入れない、人物の特定はしない。
- 締切内の補足のため、ユーザーに伝えたうえで次を簡略化する: 友達はデモ利用者に初期登録（招待コードは作らない）、在場判定はブラウザが送る位置で行う。

## Decision
- `apps/eden-system/` に独立したアプリとして置く（独自の `pyproject.toml`・`uv.lock`・テスト、ポート 8766）。
- Flask + Jinja、保存は標準ライブラリの SQLite（`apps/eden-system/instance/`、Git 管理外）。地図は同梱の Leaflet 1.9.4（ハザードマップナビと同じハッシュ確認済みの配布物）。
- 決定的に扱うもの: 距離判定（書き込み50m、カメラ越し表示200m）、公開範囲（パブリック／本人／友達）、プライベートの24時間期限、写真のメタデータ除去と縮小。
- AI（Claude Code CLI、既存認証）: 写真から主な対象（建物・看板・モノ）を認識し、近くの既存の対象と同じかを判定する。人物は認識しない（人物が主対象なら結び付けない）。
  CLI は写真だけを置いた一時フォルダで、ツールは Read のみ・`dontAsk`・MCP なしで起動する（ハザードマップナビの前に検討した写真比較の試作で検証した方式）。
  パブリック投稿は AI で内容を確認する（悪口・個人情報・他人の居場所）。AI を使えない場合はモック（決定的）に切り替えられる。
- 外部AIへの写真送信は画面上の同意があるときだけ。

## Consequences
- 在場判定は偽装できる。本番では端末側の位置の検証やサーバー側の不正検知が要る。
- 方位センサーの精度は端末差が大きい。PC では方角をスライダーで指定する。

## Verification

- `./scripts/check.sh`（両アプリのテストとモック評価をまとめて実行）
