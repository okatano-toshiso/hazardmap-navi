# EDEN SYSTEM 仕様（ドラフト）

状態: 2026-11-25 ユーザーが初期値のまま作成を指示し、補足の試作として実装した（ADR 0003、`apps/eden-system/`）。
簡略化（ユーザーに伝達済み）: 友達はデモ利用者に初期登録（招待コードなし）、在場判定はブラウザが送る位置で行う。

## 一言で

現実の場所（緯度経度）と、そこにある建物・看板・モノにコメントを残し、その場所に来た人だけが読み書きできるアプリ。
発想の元はアニメ「東のエデン」の東のエデンシステム（画像認識で対象に情報を結び付ける）と、セカイカメラ（GPS で情報を分類）。
アプリ名は「EDEN SYSTEM」。

## 位置づけ（ユーザー決定）

- 採用課題の追加提出物。ハザードマップナビと並べて提出する。
- main ブランチ内の別フォルダに、別アプリとして作る（依存・起動・テストを分ける）。

## 決まったこと（2026-11-24 ユーザー回答）

| 項目 | 決定 |
|---|---|
| 公開範囲 | パブリック（誰でも見られる）とプライベート（友達登録した人だけが見られる）の2種類 |
| 使い方の例 | プライベート: 待ち合わせ場所に「ちょっと離れている。待ってて」／パブリック: 「この先のラーメン屋はおいしい！」 |
| 書き込み | その場所に実際にいるときだけ書ける |
| AI（東のエデン要素） | 撮った写真から建物・看板・モノを認識し、GPS に加えてその対象にコメントを結び付ける |
| 表示 | カメラ越し（方角に合わせてコメントを浮かべる）と、地図の両方 |
| 広告 | 将来の収益モデルとして企画書にだけ書く。試作には入れない |

## 作らないこと（安全・プライバシー）

- **人の顔や姿からの個人の特定・プロフィール表示はしない。** 作中の「すれ違った人のプロフィールが見える」機能は、本人の同意なく個人を識別するため作らない。
  写真に写った人は認識の対象にせず、AI にも人物の属性を推測させない。
- 他人の現在地や移動の記録を表示しない。

## 提案している初期値（要確認）

| 項目 | 初期値の案 | 理由 |
|---|---|---|
| 書き込める距離 | その地点から半径50m以内 | GPS の誤差（数十m）を吸収しつつ「その場にいる」を担保する |
| 閲覧できる距離 | カメラ越しは半径200m、地図は対象地域全体 | 近づくと見える体験と、デモのしやすさの両立 |
| プライベートの期限 | 24時間で自動的に消える | 待ち合わせ用途に合い、位置の記録が残り続けない |
| 友達登録 | お互いの承認が必要。試作では招待コード方式 | 一方的に相手を追加できないようにする |
| パブリック投稿の確認 | AI で悪口・個人情報・他人の居場所をさらす内容を確認し、載せない | 公開の場の安全 |
| 写真 | 位置情報などのメタデータを除去・縮小。保存するのは認識結果と縮小画像のみ | プライバシー |
| アカウント | 試作では、用意したデモ利用者を切り替えて使う（ログイン機能は作らない） | 締切内で友達・公開範囲の動作を示す |
| 位置の扱い | スマホでは GPS、PC では地図で現在地を指定 | ローカル環境で再現できるようにする |

## 試作で確かめること（採用課題向けに絞った範囲）

1画面で次を動かす:

1. 現在地（または地図で指定）の近くのコメントを、カメラ越しと地図で表示する
2. その場で写真を撮ると、AI が建物・看板・モノを認識し、その対象にコメントを残せる（パブリック／プライベートを選ぶ）
3. 別の利用者に切り替えると、友達だけがプライベートのコメントを見られる
4. 同じ対象をもう一度撮ると、AI がそれを認識して、結び付いたコメントを出す

## 技術上の注意

- スマホのブラウザでカメラ・位置・方位センサーを使うには HTTPS が必要（PC の localhost は例外）。スマホ実機での確認にはローカルの HTTPS が要る。
- 方位センサーの精度は端末差が大きく、カメラ越しの表示位置はずれることがある。地図表示を必ず併用する。
- 画像認識は外部AI（Claude）を使う場合、写真を外部へ送るため明示的な同意を取る。
